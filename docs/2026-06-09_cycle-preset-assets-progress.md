# Progress

## Goal

Move built-in cycle preset phase, observer lane, assist lane, state schema, expressions, and runtime action definitions out of TypeScript factory code into a maintainable data asset.

## Done

- Added `src/assets/json/cycle-presets.json` as the source of truth for built-in cycle presets.
- Refactored `src/utils/cycle-presets.ts` into a thin asset reader that preserves the existing `cyclePresetOptions`, `buildCyclePreset`, and `getCyclePresetLabel` API.
- Kept profile construction unchanged: role profile seeds still reference cycle presets by `rotation_id`.
- Added a regression test that preset options are derived from the cycle preset asset.

## Files Changed

- `src/assets/json/cycle-presets.json`
- `src/utils/cycle-presets.ts`
- `src/__tests__/cycle-presets.test.ts`

## Root Cause / Key Decision

Cycle presets were previously generated by TypeScript helper functions, which made phase and lane editing code-centric. The new JSON asset makes built-in rotations inspectable and maintainable as data while keeping runtime behavior behind the same API.

## Logs / Tests

- `pnpm.cmd exec vue-tsc --noEmit`
- `pnpm.cmd test -- src/__tests__/cycle-presets.test.ts src/__tests__/role-profile-templates.test.ts src/__tests__/profile-validation.test.ts`

## Risks

- The JSON file is intentionally verbose because every skill slot stores its resolved expressions, attempt policy, and runtime actions inline.
- The preset ID union is still maintained in TypeScript. Adding a third built-in preset needs both the JSON entry and the `CyclePresetId` union update.

## Next Step

Add lightweight asset validation for duplicate preset IDs, missing phase targets, and malformed skill slots so data mistakes fail with clearer errors.
